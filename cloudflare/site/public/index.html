// 01SAFE BY DEFAULT

It asks before it touches your machine.

Most agents ask you to trust them. Neko makes trust unnecessary: the tools that can change something are a different category from the tools that only look, and the boundary is auditable rather than promised.

  • Reading is free, changing is not. read, search, glob and list run immediately; write, edit and bash wait for you.
  • Autonomy is a named state. Turning approvals off is an explicit mode, not a hidden default - and it is visible while it is on.
  • The boundary is audited. neko policy re-derives it from the code and fails loudly if it ever drifts.
  • Contained by the OS. Bash runs in a real sandbox where one exists, and escaping the project directory is refused everywhere.

// 02ANY MODEL, INCLUDING NONE OF THEIRS

A new model is a line of config, not a new release.

Neko talks to any OpenAI-compatible endpoint. That includes a hosted API, your work account, and a model server running on your own machine - which is what makes it genuinely offline-capable rather than offline-marketed.

  • Subscriptions or keys. ChatGPT, Claude, Gemini, Grok, Kimi, DeepSeek - or any endpoint you can reach.
  • Or nothing at all. Point a profile at llama.cpp or Ollama and no byte leaves the machine.
  • Switch mid-task. /provider and /model change the endpoint live; the conversation survives.
  • Keys stay yours. Read on demand from the environment, never stored in the project, never printed.
A LOCAL PROFILE~/.neko-core/config.json
{
  "active_profile": "local",
  "profiles": {
    "local": {
      "base_url": "http://127.0.0.1:8080/v1",
      "auth": "none"
    }
  }
}

That is the entire change. No plugin, no rebuild, no key.

// 03THE ORACLE

A second opinion - from a model with no hands.

When Neko is stuck, it can send a curated slice of your project to a different, stronger model. That model gets no tools at all: it advises, it does not act. If the advisor also had hands it would just be a second agent, and you would pay twice for the same context.

  • Nothing leaves silently. The manifest of what is being sent prints first, every time. --dry-run sends nothing at all.
  • Secrets are refused, not trimmed. A credential store is dropped whole; a key-shaped literal is masked in place.
  • Your code stays readable. Only string values are touched, so process.env.API_KEY survives - masking it would corrupt what you asked to have read.
  • Approval-gated. Neko cannot consult on its own. Sending source off the machine has the same bar as running a shell command.

// 04YOURS TO SHAPE

One Markdown file teaches it a new job.

Neko is a coding agent out of the box, but it is not limited to coding. A skill is a folder with a Markdown file in it; Neko loads the full instructions only when a task actually matches, so breadth costs you nothing in context.

  • Skills. Write how you want a job done once. Neko finds it when the job comes up.
  • MCP. Any MCP server plugs in; an existing project .mcp.json works untouched.
  • Memory. Decisions persist across sessions, and every entry is a file you can read or delete.
  • Subagents. Hand a side investigation its own context so it never clutters the main thread.
A SKILLskills/procurement/SKILL.md
---
name: procurement
description: sourcing, quotes, supplier checks
---

# When to use this
A request to buy, price, or compare suppliers.

# Rules
- Never commit to a purchase. Humans approve.
- Quote in VND, and name the source of every price.

Paste one line

Copies the right build for your machine and puts neko on your PATH, so you can type it in any terminal afterwards. It also handles updates.

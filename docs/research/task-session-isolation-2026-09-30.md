## Problem and present evidence

`createTaskScope`/`ToolRegistry.bindTaskScope` already gate scoped memory, but no production CLI, TUI or ACP caller activates them (`src/core/task-scope.ts:15`, `src/core/tool-runtime.ts:542`). Session v2 has one cwd and one flat messages array (`src/adapters/session.ts:42`). TUI `/resume` replaces that array, while ACP loads the flat array (`src/ui/chat.tsx:1006`, `src/adapters/acp.ts:700`). A same-session A→B→A journey can therefore feed B's history or summary back into A even if memory search itself is scoped. Direct TUI `/memory`, `/remember --user` and `#` bypass the registry scope (`src/ui/commands.ts:1414`, `src/ui/chat.tsx:2052`). The environment snapshot cache key is cwd/model/provider, without task or activation revision (`src/adapters/context.ts:225`). Compaction keeps a historical first request and a model-written capsule, not structured source lineage (`src/core/agent.ts:449`). These are source findings; user-reported wrong recall has not yet been reproduced end to end with a real model.

## Decision for the first vertical slice

Introduce **opt-in task-mode sessions** with exactly one explicit active task. Neko owns task identity, transcript selection, memory admission and compaction. Each task has a runtime-generated opaque ID, a human label, an existing canonical physical root, its own `Agent`, `ToolRegistry`, working transcript and turn state. A separate ordered, task-labeled UI event timeline may show the whole session, but **never becomes model working history** merely because it is visible. An ID in model text, tool arguments, ACP prompt content or a deserialized object is never authority. Each entrypoint validates the root allowed under its existing host contract; `TaskScope` is reconstructed by runtime after that check. Selecting a task does not grant access to its root: the existing host/permission/capability checks still decide filesystem and process access.

Task transitions happen only after the previous turn, approval, child work, detached/background jobs, queued TUI input and compaction have settled or have been explicitly cancelled with a known outcome. Neko checkpoints A with a **new single-writer/revision check** (the current `Session.revision` is not a CAS), verifies the target root, constructs a fresh registry and Agent for B, binds the scope before any memory/context read, then loads **only B's** working transcript. A→B→A restores A's checkpoint. A failed or cancelled transition leaves A active and its raw checkpoint usable. Never rebind a registry or merely replace `Agent.messages`: Agent and registry hold additional task-specific state and bind only once. Approval decisions cached for a task must not silently carry into another task.

Use one coordinator in Neko's adapter layer for the three entrypoints. CLI `run` currently has no durable Session; an explicit one-shot task must be either marked ephemeral or resolve a previously created task through a new validated store command. The TUI exposes create/use/list/status commands and shows the active root; ACP exposes the same semantics as a Neko command/extension, not a second Wiii model loop. The **first shippable slice switches same-root tasks in all three entrypoints**. TUI currently captures config and `process.cwd()` once, so cross-root support must rebuild config/runtime from the target root, never carry A's config/trust to B. ACP v1 accepts an existing absolute client-supplied `cwd`, then fixes it for load/resume and rejects additional roots (`src/adapters/acp.ts:169,319,804`). A same-root task slice can use that **saved ACP cwd without increasing existing authority**. Cross-root coordinator tests use a synthetic trusted host-grant fixture, while production rejects cross-root switching until a launcher-owned allowed-root capability is supplied outside model/prompt content and enforced by Neko. A model/client text path is not such a new grant. CLI/TUI root changes also retain existing filesystem permissions and require an explicit user action.

## Durable format and legacy rule

Do not add optional task fields to schema-v2 flat sessions: older binaries could ignore the fields and replay a scoped transcript as legacy. Define a separately validated, opt-in task-session format/store **invisible to old session pickers/writers**, with session ID, active task ID, per-task `{id,label,canonicalRoot,revision,workingMessages}`, an ordered task-labeled UI event timeline and a journal/recovery marker. ACP v1 replay currently uses one Agent's messages; task-mode replay needs an explicit versioned event/active-task contract so the client never mistakes all UI events for model input. Document rollback to the legacy binary as leaving task sessions unavailable but untouched; do not convert them into v2. Legacy v2 bytes and legacy memory stay where they are; loading them remains legacy behavior. Task mode cannot read or import their prose or memory automatically. Explicit import must show source and destination, copy without deleting source, and record digest/provenance. A serialized `TaskScope` is data, never a trusted object. If a saved task's physical root is missing or changed, resume stops before context or memory admission. A task-session writer must hold one lease across CLI/TUI/ACP and reject stale revisions; existing ACP has a lease, while existing TUI does not.

Compaction must bind a capsule to the exact task and source event range. Keep durable raw source events outside the model's bounded prompt: event ID, task ID, canonical root, observed source path and content revision when known, digest and event sequence/revision. Source metadata must come from trusted tool/file observations, **not** model-supplied arguments alone. A summary may cite those IDs, but its prose cannot create provenance. On repeated compaction, preserve the original event references and retrieve raw evidence for verification; do not treat a newly timestamped summary as a fresh file observation. Commit a capsule only if both transcript and task/session revisions still match the snapshot. If raw events are in a separate journal, acknowledge their durable commit **before** the capsule points at them, and recover an acknowledgement-lost outcome without blind replay. A single-file atomic checkpoint is an alternative for the first slice, subject to the current session size bound and measured duplication. Failed/empty/truncated/stale summaries retain the previous working context. A bounded prompt may omit old raw content, but the stored source lineage must remain retrievable. Until this is implemented and tested, no original-provenance guarantee is claimed.

Scoped memory/history admission is not a promise that tools cannot read another permitted root or that a model forgets previous prompts. **Task mode must quarantine legacy procedural memory too:** global `NEKO.md`, `~/.neko-core/workflows` and `playbook.md` are not auto-injected, searched, read or written through unscoped tools until an explicit shared/import policy with provenance exists. The active root's project instructions such as `NEKO.md` can be admitted as labeled project context with path/revision, never silently promoted to a task fact; same-root tasks intentionally share that source. In task mode, direct `/memory list/read/forget` and `#` must use the active scoped store/root; `/remember --user` must fail closed until an explicit shared-memory route with provenance is defined. `/memory on/off` is a global user setting and must display its cross-task effect; `/memory identity` must show the active task binding without disclosing quarantined legacy content. No direct command may bypass the same admission gate. This does not change ordinary legacy-session behavior.

## Deterministic regression contract (RED first, no model/network/desktop)

| Case | Acceptance | Current expected result |
| --- | --- | --- |
| Two roots `A/app` and `B/app`, both with `config.ts` and `stack.md`, conflicting pnpm/bun facts; A→B→A through the coordinator with a **synthetic trusted host grant** | Provider history, turn context, tool root, memory index/search/direct-ID and writes contain only active task; A resumes its own transcript. Production must reject B without such a grant | No production task coordinator or cross-root grant contract |
| Same physical root, two task IDs with conflicting facts and A→B→A through CLI/TUI/ACP | Model working history excludes inactive task even when UI timeline displays both; this is the first release gate | Root filter alone cannot isolate the flat session history |
| UI replay after task switch and restart | Ordered events keep task labels; ACP/TUI can show history while the provider receives only active task messages | ACP replay currently reads one flat Agent history |
| Direct TUI `/memory read/list/forget`, `/remember --user`, `#` under B | Same runtime admission as model memory; no legacy or A read/write | Direct paths currently unscoped |
| Global workflow/playbook and global `NEKO.md` contain an A-only procedure/fact | B receives no legacy index/content via prompt or direct tool read/search/write unless explicitly shared/imported; project-local instructions are labeled with source | Current turn context/tool surface exposes unscoped stores |
| Restart/resume while B active, then return to A; missing/moved root; forged scope JSON | Recreate scope only from validated saved ID/root and host authority; fail closed on mismatch; leave v2 bytes untouched | Schema v2 has flat messages/cwd |
| Same cwd/task switch and branch or file revision change | Environment cache recaptures or carries explicit snapshot revision; fresh file observations outrank older summaries | Cache key lacks task/revision |
| Two fake-provider compactions where summaries deliberately omit paths, with A correction after first and B fact unchanged | Original event IDs/root/path/revision/digests remain retrievable after second compact and restart; A correction does not erase B fact | Capsule currently contains model prose only |
| Switch during pending model, approval, child, checkpoint or compaction | Reject/defer atomically without cross-task state or lost messages | No transition API |
| Switch with a background Bash job or picker-held TUI queue; ACP `always allow` granted only in A | No queued prompt retargeted to B; no approval or provider continuation reused in B | No task transition boundary |
| CLI/TUI/ACP conformance for same root, ACP request for ungranted B root | Neko uses shared semantics; ACP v1 rejects B before runtime/memory read | No task command/host grant |

Initial no-model tests should use temporary synthetic repositories and fake provider responses; do not inspect or migrate a user's real sessions. Start with a RED contract test for runtime activation and same-root A→B→A, then a RED compaction provenance test whose fake summarizer omits paths; each should assert behavior through the task-session boundary, not by checking implementation fields. Current source has no such boundary, so an absent-API failure is expected and must be labeled as such, not reported as a reproduced user incident. Keep raw RED logs and distinguish it from an observed wrong result. Run the source-focused tests before any native UIA/ConPTY/GUI test, which remain reserved for the Wiii desktop handback. Full Windows candidate gate has priority once ownership returns.

## Review/rollout boundary

This ADR is proposed, not a compatibility change yet. Review the root authority, durable schema and ACP command with Wiii integration owner before exposing them. Ship the first slice only after deterministic **same-root** A→B→A, restart, direct command and cross-root denial conformance pass across CLI/TUI/ACP; keep the cross-root host-grant fixture as a coordinator test until a versioned production contract exists. Preserve old session readers and snapshots; do not silently import memory or alter billing, sandbox or host capabilities. Source-only success is not native GUI or model-quality evidence.
